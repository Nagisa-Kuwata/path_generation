# Feature Specification: ロボットリアルタイム経路生成・迷路走破シミュレータ

**Feature Branch**: `001-robot-maze-simulator`  
**Created**: 2026-03-24  
**Status**: Draft  
**Input**: User description: "ロボットのリアルタイム経路生成と迷路の生成, 走破シミュレータ"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 迷路の自動生成と探索開始 (Priority: P1)

ユーザーがシミュレータを起動すると、12m×12m のランダム迷路が生成される。  
ユーザーは UI 上の「開始」ボタンを押すことで、迷路中央に配置されたロボットが  
外周の目標位置へ向かう探索を開始する。

**Why this priority**: 迷路生成とロボット探索の開始はシステムの核心機能であり、  
他のすべてのユーザーストーリーの前提となる。

**Independent Test**: シミュレータを起動し「開始」をクリックするだけで、ロボットが  
迷路内を自律的に動き始め目標へ向かう様子を確認できる。

**Acceptance Scenarios**:

1. **Given** シミュレータが起動済みの状態で、**When** ユーザーが「開始」ボタンをクリックすると、  
   **Then** ロボットが迷路中央から移動を開始し、1 m/s の一定速度で経路を進む。
2. **Given** 迷路が生成された状態で、**When** 生成結果を確認すると、  
   **Then** 開始位置（中央）から外周の目標位置へ至るルートがちょうど 1 本存在する。
3. **Given** 「開始」ボタン押下前の状態で、**When** UI を確認すると、  
   **Then** 迷路マップ・開始位置・目標位置が表示されており、ロボットは静止している。

---

### User Story 2 - LRF によるリアルタイムマップ更新 (Priority: P2)

ロボットは LRF（測距センサ）を使って周辺を逐次スキャンし、  
取得した点群情報を元に保有マップをリアルタイムで更新しながら経路を生成する。

**Why this priority**: 未知環境の逐次探索がこのシミュレータの中核的な価値であり、  
単体で「未知環境スキャン→マップ更新→経路再生成」の流れを実証できる。

**Independent Test**: 探索中の任意の時点で UI のロボット保有マップを確認し、  
ロボットが通過・観測した領域のみが更新されていることを検証できる。

**Acceptance Scenarios**:

1. **Given** ロボットが探索中の状態で、**When** LRF がスキャンサイクルを完了すると、  
   **Then** 360°・角度分解能 0.5°・検出範囲 5 m の点群情報が 50 回/s で取得される。
2. **Given** LRF データが取得された状態で、**When** ロボットがマップを更新すると、  
   **Then** 壁の位置情報が既知領域として保有マップに反映される。
3. **Given** ロボットがまだ観測していない区画が存在する状態で、**When** その区画を確認すると、  
   **Then** 保有マップ上では未知（空白）として表示される。
4. **Given** スキャンレイが壁に当たる状態で、**When** LRF が距離を計測すると、  
   **Then** 壁を貫通した先の情報は取得されない。

---

### User Story 3 - 経路生成とロボット移動 (Priority: P3)

ロボットは保有マップを常に参照し、0.5 m×0.5 m のボディサイズを考慮した  
通行可能経路をリアルタイムで生成し、目標位置へ向かって移動する。

**Why this priority**: 経路生成はマップ更新（US2）に依存するが、単体で  
「経路表示→移動」の完全な動作フローとして検証可能。

**Independent Test**: 保有マップ上の経路ラインを確認し、壁への衝突がなく、  
かつロボットのボディサイズが通過不能な狭路を通っていないことを検証できる。

**Acceptance Scenarios**:

1. **Given** ロボットが探索中の状態で、**When** 保有マップが更新されると、  
   **Then** 目標位置へ向かう経路（ベクトル含む）が即座に再生成され UI に反映される。
2. **Given** 経路が生成された状態で、**When** 経路の幅を確認すると、  
   **Then** 経路上のすべてのセグメントでロボット（0.5 m×0.5 m）が通行可能な空間が確保されている。
3. **Given** 経路が生成されている状態で、**When** ロボットが移動すると、  
   **Then** 壁または障害物との衝突が発生しない。

---

### User Story 4 - UI によるシミュレーション可視化 (Priority: P4)

ユーザーは UI で迷路全体・ロボット保有マップ・LRF 点群・生成経路・進行方向ベクトルを  
リアルタイムに確認でき、「再起動」ボタンで即座に新しい迷路に切り替えられる。

**Why this priority**: 可視化機能はシミュレータとしての体験品質に直結するが、  
内部ロジック（US1?3）が完成した後に追加・改善しやすい独立した層として切り出せる。

**Independent Test**: 探索中に「再起動」をクリックするだけで新しい迷路が生成され、  
UI が初期化状態に戻ることで独立検証できる。

**Acceptance Scenarios**:

1. **Given** シミュレーション実行中の状態で、**When** UI を確認すると、  
   **Then** 実際の迷路マップ・開始位置・目標位置・LRF 点群・保有マップ・生成経路・進行方向ベクトルが同時に表示される。
2. **Given** 探索中または探索完了後の状態で、**When** ユーザーが「再起動」ボタンをクリックすると、  
   **Then** 新しいランダム迷路が生成され、ロボットは「開始」前の静止状態に戻る。
3. **Given** 「再起動」後の状態で、**When** 目標位置を確認すると、  
   **Then** 前回の実行とは異なる外周上の位置が設定されている（毎実行ごとにランダム）。

---

### Edge Cases

- ロボットが袋小路に突入した場合、バックトラックして別ルートを探索できるか？
- LRF の射程内（5 m）に壁がまったく存在しない方向がある場合、正しく「開放空間」として処理されるか？
- 目標位置が LRF 射程外のまま探索が続いた場合、経路がどのように暫定生成されるか？
- 「開始」ボタン押下直後にすぐ「再起動」をクリックした場合、状態が正しくリセットされるか？
- ロボットが目標位置へ到達済みの場合、追加の移動や経路生成が行われないか？

## Requirements *(mandatory)*

### Functional Requirements

**迷路生成**

- **FR-001**: システムは起動のたびに 12 m×12 m のランダム迷路を自動生成しなければならない（MUST）。
- **FR-002**: 生成された迷路は、開始位置（中央）から目標位置（外周のランダムな 1 点）へ至る  
  ルートがちょうど 1 本だけ存在することを保証しなければならない（MUST）。
- **FR-003**: ロボットの目標位置は毎実行ごとに外周上のランダムな位置へ変更されなければならない（MUST）。
- **FR-004**: ロボットの開始位置は迷路の中央（座標原点）に固定しなければならない（MUST）。

**ロボット挙動**

- **FR-005**: ロボットは 1 m/s の一定速度で移動しなければならない（MUST）。加速・減速は考慮しない。
- **FR-006**: ロボットは 0.5 m×0.5 m のボディサイズを持ち、そのサイズが通過不能な経路を生成してはならない（MUST NOT）。
- **FR-007**: ロボットは初期状態で迷路マップ情報を一切保持してはならない（MUST NOT）。

**LRF センサ**

- **FR-008**: ロボットは LRF によりロボット中心からの 360° 全方位をスキャンしなければならない（MUST）。
- **FR-009**: LRF は角度分解能 0.5°・検出範囲 5 m・50 回/s でデータを取得しなければならない（MUST）。
- **FR-010**: LRF の計測は壁を貫通しない範囲の点群情報のみを取得しなければならない（MUST）。

**マップ管理・経路生成**

- **FR-011**: ロボットは LRF で取得した点群情報をもとにマップを随時更新し、内部に保持しなければならない（MUST）。
- **FR-012**: ロボットは保有マップを参照して目標位置への経路をリアルタイムで生成しなければならない（MUST）。
- **FR-013**: 経路および進行方向ベクトルはマップ更新のたびに再計算されなければならない（MUST）。

**UI**

- **FR-014**: UI は以下の情報を同時に表示しなければならない（MUST）：  
  実際の迷路マップ、開始位置、目標位置、LRF 点群情報、ロボット保有マップ、生成経路、進行方向ベクトル。
- **FR-015**: UI には「開始」ボタンを設け、クリック時にロボットの探索処理を開始しなければならない（MUST）。
- **FR-016**: UI には「再起動」ボタンを設け、実行中・完了後のいずれの状態でもクリック可能で、  
  クリック後は新しい迷路を生成して「開始」前の状態に戻らなければならない（MUST）。

### Key Entities

- **Maze（迷路）**: 12 m×12 m のグリッド構造。壁の位置情報、開始位置、目標位置を保有。  
  毎実行ごとに再生成される。
- **Robot（ロボット）**: 0.5 m×0.5 m のエージェント。現在座標、進行方向、保有マップ、  
  生成済み経路を保有。
- **KnownMap（保有マップ）**: ロボットが LRF によって逐次取得・蓄積した環境情報。  
  既知領域・未知領域・壁位置を区別して管理する。
- **LRFScan（スキャンデータ）**: 360° 点群情報のスナップショット。各点は距離と角度で表現される。
- **Path（経路）**: 現在位置から目標位置までのウェイポイント列。保有マップ更新ごとに再生成される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 起動から迷路表示まで 3 秒以内に完了し、ユーザーが「開始」を即座に押せる状態になる。
- **SC-002**: ロボットは 1 m/s の速度で停止・ジャンプすることなく連続的に移動し、壁との衝突がゼロである。
- **SC-003**: LRF データは 50 回/s（20 ms 周期）でシミュレーション内に処理され、保有マップが遅延なく更新される。
- **SC-004**: 生成されたすべての迷路で、開始位置から目標位置へのルートがちょうど 1 本だけ存在することが  
  自動検証で確認できる。
- **SC-005**: ロボットはすべての迷路パターンで最終的に目標位置へ到達できる（探索成功率 100%）。
- **SC-006**: UI のリアルタイム更新が視覚的な遅延（1 フレーム以上の描画遅れ）なく行われる。
- **SC-007**: 「再起動」ボタン押下から新しい迷路の表示完了まで 3 秒以内に完了する。

## Assumptions & Constraints

- 迷路は連続する 2D 平面上に構築され、階層構造（3D）は持たない。
- 迷路のグリッドセルサイズは 0.05 m×0.05 m とする（12 m / 0.05 m = 240 セル四方）。
- 壁は有限厚さを持ち、厚さは 0.1 m（= 2 セル分）とする。
- 迷路外周には通路となる開口部を設ける。目標位置はその開口部のセル（外周セル単位）とする。
- ロボットの移動空間は連続座標（最小単位 0.05 m = 1 セル）上の全方位自由移動とする。
- ロボットは姿勢（向き）を持たない。移動ベクトルが進行方向を示す。
- 未知領域への探索戦略は「最近傍未知領域」方式とする。
- 経路は LRF 更新ごと（50 Hz）に毎回再生成する。
- 到達判定：ロボット中心座標と目標座標の距離 ? 0.05 m で到達とみなす。
- 到達時にシミュレーションは自動停止し、ロボットの枠色が淡い赤 → 淡い青に変わる。
- シミュレーション時間は実時間ベース（1 m/s = 実時間 1 秒で 1 m 移動）。
- 探索の制限時間は設けない。
- UI は実際の迷路マップとロボット保有マップを重畳表示する。
- UI 色分けルール：壁=黒、通路=白、未知領域=グレー、LRF 点群=淡い緑、経路=赤、
  到達前ロボット=淡い赤、到達後ロボット=淡い青、目標位置=橙。
- UI 目標フレームレートは 30 fps（非厳格）。
- 「開始」ボタンは探索中にグレーアウトする。スピード調整ボタンは設けない。
- 座標系：迷路中央（=開始位置）を原点 (0, 0) とし、Y 軸上向きを正とする。
- 乱数シードを外部から指定することで再現可能な迷路生成をサポートする（デバッグ・テスト用途）。
- LRF は理想センサを想定し、ノイズや計測誤差は考慮しない（シミュレーション上の完全計測）。
- シミュレータはシングルユーザー・ローカル実行を前提とし、ネットワーク接続は不要。
- 迷路サイズは 12 m×12 m 固定とし、動的なサイズ変更には対応しない。
